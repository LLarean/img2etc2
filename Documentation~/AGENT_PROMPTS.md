# Промпты для агентов IMG2ETC2

Каждый блок можно отправить агенту из корня репозитория. В качестве контекста приложите рабочую ветку и, для Unity-задач, доступную версию редактора. Если установлен навык `unity-texture-prep`, его можно использовать для аудита и подготовки тестовых изображений. Промпты работают и без него.

## Проверка состояния перед работой

> Проверь IMG2ETC2 на текущем SHA. Прочитай README и `Documentation~/FIX_PLAN.md`, затем проследи путь от выбора папки до записи и импорта текстуры. Собери `.unitypackage` во временную папку и проверь содержимое архива. Unity запускай только в отдельном тестовом проекте. Укажи, какие дефекты воспроизведены, какие видны по коду и какие требуют проверки в редакторе. Исходники оставь без изменений.

## Автосборка и проверка архива

> Выполни шаг проверки архива из `Documentation~/FIX_PLAN.md`. Собери текущий архив для сравнения, затем исправь `build_unitypackage.py`. Добавь проверку списка поставляемых файлов, путей `Assets/IMG2ETC2/`, папочных записей, GUID и коллизий. Запускай проверку в PR и сохраняй архив как артефакт. Проверь случаи, когда в архиве отсутствует обязательный файл или повторяется GUID. Публикацию и теги оставь для отдельной задачи.

## Безопасная запись и EditMode

> Выполни шаг «Безопасная конвертация и EditMode» из `Documentation~/FIX_PLAN.md`. Начни с одного сценария: положи в изолированный тестовый проект `sample.jpg` и уже кратный четырём `sample.png`, затем проверь, что после обработки оба файла и их `.meta` побайтно совпадают с исходными. Запиши версию Unity и команду прогона. Исправь конфликт назначений и закрепи его EditMode-тестом. Сохранение GUID, прозрачные поля и обработку битых файлов бери отдельными небольшими изменениями. Если Unity не запустилась, приложи причину из лога и перечисли сценарии, которым ещё нужен прогон.

## Запуск Unity в CI и подготовка релиза

> Когда проверка архива и локальные EditMode-тесты готовы, подключи те же проверки в CI. Используй согласованный runner и закреплённую версию Unity. Сохраняй XML и лог, включая неуспешные прогоны. Проверь импорт артефакта в чистый проект. Для релиза добавь сверку тега с `package.json` и зависимость публикации от проверок. Для приёмки используй тестовый запуск без публикации и проверь, что несовпадающая версия блокирует релизный шаг.
